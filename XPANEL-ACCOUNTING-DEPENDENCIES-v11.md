# v11 accounting association and dependency qualification

Pinned upstream retains client-global accounting after inbound deletion and reuses SQLite inbound IDs when empty. An unrelated new inbound then displayed old client statistics because the retained legacy inbound_id pointed to the reused ID. Actual authenticated API reproduction verified this. No cross-client billing or enforcement effect was established.

Deletion now transactionally repairs invalid display ownership to the lowest surviving linked inbound or -1 for a detached global client. Migration repairs previously stale associations. Global totals, clients, quota, expiry, reset and other lifecycle fields are preserved. Zero remains legacy orphan-cleanup semantics, so detached retained history uses -1. Generic DetachInbound remains unchanged because node replacement uses it during an intermediate state; its existing history/owner regression still passes. Existing accounting APIs join membership for sibling totals.

Tests cover exact ID reuse and API display, shared membership, global retention, stale migration, expiry/overquota detached client versus unrelated replacement, unrelated inbound reset and new-client reset. Entire service suite passes. The fix is not a proof of all concurrency, remote accounting, or billing workflows. No real user state was used.

Dependency overrides pin glob14.0.2 and minimatch11.0.1, replacing affected transitive versions without downgrading Swagger/Storybook. Registry audit reports zero known advisories at the recorded check; this is not a security guarantee. Typecheck, production build and all87unitfiles/1422tests pass. Generated frontend files are byte-identical to v10. ApiDOM imports minimatch from its Node filesystem resolver; its browser export selects a separate resolver that cannot read files and has no minimatch import. Thus this change is dependency/build hygiene, not a demonstrated browser exploit fix. Swagger UI itself is genuinely included in production assets. Full component/Storybook compatibility and all future advisory status are not established by unit tests.

Integrated protocol evidence on v10/v9 binary covers authenticated panel API creation/hot-apply, exact65559-byte loopback payload and SQLite persistence for VLESS/VMess/TrojanTLS/ShadowsocksAES-GCM/mixedSOCKS/HTTP, followed by API cleanup. Single-client TCP only, no broad transport/UDP/REALITY/Vision/provider/subscription guarantee. Initial production counter poll intentionally records a baseline and does not charge earlier bytes; tests wait for that poll. No full startup-usage accounting guarantee.
